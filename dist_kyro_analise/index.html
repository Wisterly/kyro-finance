1. Correção da Reutilização de Tokens e Preservação de Geração

Anteriormente, releaseLease apagava o documento usado para calcular o próximo token via t.delete(leasePath). Com isso, a reaquisição por qualquer processo (inclusive o mesmo titular) recomeçava em 1. A correção mantém o registro inativo no storage com o último fencingToken persistido (definindo holderId: '' e expiresAt: 0), garantindo que o avanço da geração seja executado na mesma transação atômica da nova aquisição.

// src/engine/concurrency.ts -> releaseLease - t.delete(leasePath); + // Ao invés de apagar o documento e perder a sequência numérica, marca como liberado + // zerando titular e expiração, preservando a última geração do fencingToken para futuras reaquisições + const releasedRecord: LeaseRecord = { + ...existing, + holderId: '', + expiresAt: 0, + updatedAt: Date.now() + }; + t.set(leasePath, releasedRecord);
// src/engine/concurrency.ts -> acquireLease (Mesma Transação) + // Se existing possui holderId vazio ou expiresAt = 0, avança a geração monotonicamente: + const nextToken = (existing?.fencingToken || 0) + 1; // Quando o lease é liberado com token 2, a reaquisição pelo mesmo titular recebe token 3 incondicionalmente!
