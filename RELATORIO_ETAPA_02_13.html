02

Revisão Bancária Estrita de Cartões: Não Dedução Automática de Saldo Credor

Diretriz Contábil e Bancária:

O saldo credor do titular NÃO é abatido automaticamente do limite comprometido junto ao emissor. O limite informado pelo banco representa a linha de crédito concedida formalmente. As compras do usuário consomem diretamente essa linha. O saldo credor próprio é mantido segregado como ativo do titular em conta gráfica, compondo o Poder de Compra Estimado pelo App, sem inflar o limite do emissor.

// Formulação Bancária Estrita:
// 1. Dívida Real Bruta (Passivo Integral): const totalRealDebtCents = openInvoiceDebtCents + futureInstallmentsCents + pendingAuthorizationsCents; // 2. Limite Comprometido com o Banco (SEM desconto automático de saldo credor): const bankCommittedLimitCents = totalRealDebtCents; // 3. Estimativa de Limite Disponível Puro do Banco: const calculatedAvailableIssuerLimitCents = Math.max(0, issuerReportedLimitCents - bankCommittedLimitCents); // 4. Overlimit Bancário (Dívida acima do limite contratado): const overlimitDebtCents = Math.max(0, totalRealDebtCents - issuerReportedLimitCents); // 5. Saldo Credor Próprio Segregado: const availableCreditBalanceCents = creditBalanceCents; // 6. Poder de Compra Estimado pelo App (Métrica interna combinada): const totalEstimatedPurchasingPowerCents = calculatedAvailableIssuerLimitCents + availableCreditBalanceCents;

Investigação, Correção e Comprovação da Validação de Timestamp

Diagnóstico Técnico Exato:
  • Expressão Efetivamente Utilizada no Teste: /^d{10}$/ (com barra invertida para dígitos decimais).
  • Origem da Grafia /^d{10}$/: Erro de escape de caractere no script gerador do HTML anterior (generate_html_02_13_complete.js, linha 506). A expressão foi inserida dentro de uma template literal JavaScript com crases sem a barra dupla (\d), fazendo com que o Node.js consumisse a barra invertida como escape de string, emitindo ^d{10}$ no HTML de saída.
  • Situação no Código Real (api/webhook.ts): O código de produção atual não possui validação de timestamp de cabeçalho; ele apenas grava timestamp: Date.now() na linha 1.023. A validação criptográfica é requisito de especificação da futura Etapa 03.
