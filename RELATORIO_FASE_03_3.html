⚡ 2. Serialização Segura de BigInt e Ida e Volta Exata

O Firestore JS SDK não suporta nativamente BigInt. A arquitetura em camadas implementada em SafeMoneySerializer resolve o problema definitivamente: 

1. Core Financeiro (BigInt Interno Centavos) ───► 15450n
2. SafeMoneySerializer.toFirestoreCents()    ───► 15450 (IEEE 754 Safe Integer aceito pelo Firestore)
3. SafeMoneySerializer.fromFirestoreCents()  ───► 15450n (BigInt restaurado com exatidão)
Limite Seguro: 9.007.199.254.740.991 centavos (~R$ 90 Trilhões) ───► 100% aprovado sem perda de 1 centavo
Dados Legados: Float 150.50 normalizado deterministicamente para 15050n

📡 3. Fronteira de Autorização do Webhook (WhatsApp Baileys / Evolution)

Segregação estrita entre a identidade do provedor (número de telefone, remoteJid) e a identidade do usuário (UID interno):

  • Validação de Origem: Eventos recebidos exigem autenticação prévia via segredo de webhook (x-webhook-secret). Tentativas sem segredo ou com segredo inválido são descartadas.
  • Vínculo Unívoco Ativo: Telefone 558695368780 mapeado para usr_alice ──► Resolvido no servidor com status RESOLVED. Escrita autorizada sob usr_alice.
  • Vínculo Ausente: Telefone sem cadastro no sistema ──► Rejeitado com status UNBOUND. Escrita no ledger terminantemente bloqueada.
  • Vínculo Ambíguo: Telefone cadastrado para múltiplos UIDs ──► Rejeitado com status AMBIGUOUS. Escrita bloqueada para prevenir mutação ou vazamento em conta incorreta.

🗺️ 4. Blueprint de Entrada dos Canais e Protocolo de Reversão

Canal Web (SPA React)

Obtém ID Token via Firebase Auth Web SDK. Envia cabeçalho Authorization: Bearer <idToken> e X-Request-ID em toda mutação. Recursos delimitados estritamente pelo authUid verificado.

Canal APK Mobile (Android)

Sincronização offline-first com fila IndexedDB criptografada. Retries de sincronização preservam o requestId original, garantindo replay transparente sem risco de duplicidade de lançamentos.

Canal Baileys (Bot Local)

Comunicação via webhook autenticado. Resolução do remetente no servidor para o UID do usuário. Idempotência indexada por ID da mensagem do WhatsApp (wa_msg_<id>).

Canal Evolution API

Gateway externo autenticado por API Key e validação de assinatura. Resolução de vínculo no servidor antes de autorizar escritas no ledger contábil.
